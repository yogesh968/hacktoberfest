# 🌱 AI Garden Buddy

**Less scrolling. More growing.**

AI Garden Buddy turns a few details about your space (city, garden type, sunlight, experience, time) into a
personalised starter gardening plan: recommended plants, care guidance, a 7-day plan and **one small
outdoor task to do today**. The plan is generated by an **open-weight Gemma model running locally through
[Ollama](https://ollama.com)**.

Built for the **Hacktoberfest 2026 DEV Challenge, Week 1: "Touch Grass"**.

## How it works

```
┌──────────────┐  POST /api/garden-plan   ┌──────────────────┐  POST /api/chat           ┌──────────────────┐
│ React (Vite) │ ───────────────────────▶ │ FastAPI backend  │ ────────────────────────▶ │ Ollama + Gemma   │
│ :5173        │ ◀─────────────────────── │ :8000            │ ◀──────────────────────── │ :11434 (local)   │
└──────────────┘   validated JSON plan    └──────────────────┘  JSON matching a schema   └──────────────────┘
```

1. The **frontend** validates the form and sends the profile to the backend.
2. The **backend** (`backend/app/services/garden_ai.py`) builds a system prompt + user prompt and calls
   Ollama's `/api/chat` endpoint with a **JSON Schema in the `format` field** (Ollama "structured outputs").
   This constrains the model to answer in exactly the shape the UI needs.
3. The reply is parsed and **validated with Pydantic** (e.g. exactly 7 days, 2–6 plants). If it's malformed,
   the backend retries once, then returns a clear `502` error. **It never substitutes a fake plan.**
4. The frontend shows the plan in cards, labelled with the model that produced it. The "today" task
   can be ticked off and reflected on; that data stays in your browser's `localStorage`.

If the AI is unavailable, the UI shows troubleshooting steps plus a short list of *general starter tips*
that is clearly labelled **"Not AI-generated"**.

## Prerequisites

| Tool | Version used in development | Notes |
|---|---|---|
| Python | 3.12 | 3.10+ should work |
| Node.js | 24 (npm 11) | 20+ should work |
| Ollama | latest | https://ollama.com/download |
| Disk | ~1–4 GB | for the model (gemma3:1b ≈ 0.8 GB, gemma3:4b ≈ 3.4 GB) |
| RAM | 8 GB minimum, 16 GB recommended | a GPU speeds things up but is not required |

**Internet** is needed to *install* dependencies and *download* the model once. After that, generating
plans works without internet (backend and model both on `localhost`). The frontend's fonts are bundled
locally, so they don't require a network connection either.

## Setup

### 1. Install Ollama and download the model

Windows: download the installer from https://ollama.com/download, or run:
```powershell
winget install Ollama.Ollama
```
macOS / Linux: see https://ollama.com/download.

Then download the model (one time):
```bash
ollama pull gemma3:4b
# Lower-RAM alternative:  ollama pull gemma3:1b
# Apache-2.0 alternative: ollama pull gemma4:e2b   (larger download, slower on small GPUs)
```
Check that it works:
```bash
ollama run gemma3:4b "Name one easy herb for a balcony."
```

### 2. Backend (FastAPI)
```powershell
cd backend
python -m venv .venv
.venv\Scripts\activate          # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env          # macOS/Linux: cp .env.example .env
```

### 3. Frontend (React + Vite)
```powershell
cd frontend
npm install
copy .env.example .env          # macOS/Linux: cp .env.example .env
```

## Run the app

Use three terminals:

```powershell
# 1) Ollama (skip if the Ollama desktop app is already running in the tray)
ollama serve

# 2) Backend
cd backend
.venv\Scripts\activate
uvicorn app.main:app --reload --port 8000

# 3) Frontend
cd frontend
npm run dev
```

Open **http://localhost:5173**. The badge in the top-right shows `gemma3:4b ready` when everything is
connected. Interactive API docs: http://localhost:8000/docs

> The **first** plan after starting Ollama is slower because the model is loaded into memory.

## Configuration

`backend/.env` (copy from `.env.example`). **No API keys or secrets are needed.**

| Variable | Default | Meaning |
|---|---|---|
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Where Ollama runs |
| `OLLAMA_MODEL` | `gemma3:4b` | Any Ollama model tag |
| `OLLAMA_TIMEOUT_SECONDS` | `180` | Give up after this long |
| `OLLAMA_TEMPERATURE` | `0.4` | Lower = more consistent output |
| `CORS_ORIGINS` | `http://localhost:5173,http://127.0.0.1:5173` | Frontend URLs allowed to call the API |

`frontend/.env`:

| Variable | Default | Meaning |
|---|---|---|
| `VITE_API_BASE_URL` | `http://localhost:8000` | Backend URL. ⚠️ Every `VITE_` variable is visible in the browser, so never put secrets here. |

Restart the backend after editing `.env`.

> ⚠️ Ollama tags ending in `cloud` (e.g. `gemma4:cloud`) run on Ollama's servers, **not** your machine.
> The app detects this and labels plans as "via a remote Ollama server" instead of "running locally".

## API

### `GET /api/health`
```json
{
  "backend": "ok",
  "ollama_reachable": true,
  "model": "gemma3:4b",
  "model_available": true,
  "runs_locally": true,
  "detail": null
}
```

### `POST /api/garden-plan`
Request:
```bash
curl -X POST http://localhost:8000/api/garden-plan \
  -H "Content-Type: application/json" \
  -d '{"city":"Pune","garden_type":"balcony","sunlight":"partial_sun","experience":"beginner","minutes_per_day":15}'
```
| Field | Type | Allowed |
|---|---|---|
| `city` | string, 2–80 chars | required |
| `garden_type` | string | `balcony`, `terrace`, `backyard`, `indoor` |
| `sunlight` | string | `full_sun`, `partial_sun`, `shade` |
| `experience` | string | `beginner`, `intermediate`, `experienced` |
| `minutes_per_day` | int 5–240 or null | optional |

Response `200` (shape; the text is written by the model and varies between runs):
```json
{
  "plan": {
    "summary": "…",
    "plants": [
      { "name": "…", "why_it_suits": "…", "watering": "…", "sunlight": "…", "difficulty": "easy" }
    ],
    "tools": ["…"],
    "seven_day_plan": [ { "day": 1, "title": "…", "task": "…" }, "… days 2–7 …" ],
    "today_task": { "title": "…", "steps": ["…"], "duration_minutes": 10 },
    "safety_notes": ["…"],
    "uncertainty_note": "…"
  },
  "meta": {
    "source": "ollama",
    "model": "gemma3:4b",
    "runs_locally": true,
    "generated_at": "2026-10-09T10:15:00Z",
    "duration_seconds": 41.2
  }
}
```

Errors all share one shape: `{ "code", "message", "hint" }`

| Status | `code` | When |
|---|---|---|
| 422 | `invalid_input` | Bad form data (also includes a `fields` object) |
| 502 | `invalid_model_output` | Model replied but not with a valid plan (after 1 retry) |
| 502 | `ollama_error` | Ollama returned some other error |
| 503 | `ollama_unreachable` | Ollama isn't running |
| 503 | `model_not_found` | Model not pulled. The hint contains the `ollama pull` command |
| 504 | `model_timeout` | Took longer than `OLLAMA_TIMEOUT_SECONDS` |

## The AI model

### What powers the recommendations
Every plan is written by the configured Ollama model. The backend's system prompt tells it to:
favour forgiving plants for the stated light/space/experience, keep tasks realistic for the time available,
**never invent weather, frost dates or local climate data**, include safety notes (toxic plants, heat,
heavy pots, tools), and explain what it couldn't know in `uncertainty_note`. The JSON Schema generated
from the Pydantic `GardenPlan` model is passed to Ollama so the output is structured.

### Licence: open-weight, not automatically "open source"
Gemma is published by Google as **open weights**: you can download and run them yourself. The licence
**depends on the version**:

- **Gemma 3** (`gemma3:*`, the default here) is released under Google's
  **[Gemma Terms of Use](https://ai.google.dev/gemma/terms)** together with the
  [Gemma Prohibited Use Policy](https://ai.google.dev/gemma/prohibited_use_policy). This is a custom licence
  with use restrictions, not an OSI-approved open-source licence. So this project calls it
  **"open-weight"**, not "open source".
- **Gemma 4** (`gemma4:*`) is reported to be released under **Apache 2.0**. If you want an
  OSI-approved licence for the model, use `OLLAMA_MODEL=gemma4:e2b`. Check the model card yourself before
  relying on this.

Always check the licence for the exact model you deploy. *This is not legal advice.*

### Why an open-weight model is valuable here
- **Local & private by default:** garden profiles don't need to leave your computer.
- **No API key, account or per-request fee** after the one-time download.
- **Transparent & swappable:** prompt, schema and model are all visible and configurable.
- **Adaptable:** the community could fine-tune a model on regional plant knowledge.

## Privacy
- With the default config, data flows only between your browser → `localhost:8000` → `localhost:11434`.
- The backend **does not log** the city or other form inputs (only error types).
- Validation errors return field names and messages, not the submitted values.
- Task completion and reflections are stored only in your browser's `localStorage`.
- If you point `OLLAMA_BASE_URL` at another machine, or use a `*:cloud` model, your prompt (including the
  city) is sent there.

## Limitations & failure cases
- **No real-time data**: no weather, climate zone, frost dates or season. Suggestions are general.
- Small models can be **wrong or overconfident** (e.g. a plant that doesn't suit your climate). Verify with a
  local nursery or agricultural extension service, and check pet/child toxicity.
- `gemma3:1b` sometimes fails the strict schema → you'll see `invalid_model_output`. Regenerate or use a larger model.
- Speed depends heavily on hardware. CPU-only can take minutes.
- The city is free text and isn't geocoded or verified.

Backend unit tests (Ollama is replaced by a fake HTTP transport **inside tests only**):
```powershell

```

```powershell

npm run lint

```
Manual end-to-end checklist:
- [ ] Badge shows "<model> ready"
- [ ] Submitting an empty form shows inline errors and focuses the first one
- [ ] A valid form shows the loading state, then a plan with all sections
- [ ] "Copy plan" copies text; "Regenerate" makes a new plan
- [ ] "Mark as done" + reflection survive a page refresh
- [ ] Quit Ollama → generating shows "Can't connect to Ollama" + the clearly labelled non-AI tips
- [ ] Set `OLLAMA_MODEL=not-a-model` → shows the `ollama pull` hint

## Troubleshooting

| Symptom | Fix |
|---|---|
| Badge: **Backend offline** | Start the backend (`uvicorn app.main:app --reload --port 8000`) with the venv activated |
| Badge: **Ollama offline** | Open the Ollama app or run `ollama serve`. Check http://localhost:11434 |
| Badge: **Model not downloaded** | `ollama pull gemma3:4b` (or whatever `OLLAMA_MODEL` is) |
| `model_timeout` | Retry (first load is slow), close heavy apps, use `gemma3:1b`, or raise `OLLAMA_TIMEOUT_SECONDS` |
| `invalid_model_output` repeatedly | Use a bigger model, or lower `OLLAMA_TEMPERATURE` |
| CORS error in browser console | Add your frontend URL to `CORS_ORIGINS` and restart the backend |
| `'uvicorn' is not recognized` | Activate the venv first: `.venv\Scripts\activate` |
| PowerShell blocks `activate` | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
| Port 5173 / 8000 in use | Stop the other process, or change the port (and update `.env` files) |

## Project structure
```
ai-garden-buddy/
├── backend/
│   ├── app/
│   │   ├── main.py              # FastAPI app, routes, CORS, error handlers
│   │   ├── config.py            # Settings from environment variables (.env)
│   │   ├── schemas.py           # Pydantic request/response + GardenPlan schema
│   │   └── services/garden_ai.py# Prompt, Ollama call, output validation
│   ├── tests/test_api.py        # API tests with a mocked Ollama
│   ├── requirements.txt / requirements-dev.txt
│   └── .env.example
├── frontend/
│   ├── src/
│   │   ├── components/          # Navbar, Hero, GardenForm, PlanView, TodayTaskCard, …
│   │   ├── services/api.js      # All fetch calls to the backend
│   │   ├── data/                # Form options, hero sample data, non-AI starter tips
│   │   ├── App.jsx              # Page layout + plan state machine
│   │   ├── main.jsx
│   │   └── index.css            # Tailwind v4 theme (colours, fonts, animations)
│   ├── package.json
│   └── .env.example
├── docs/DEV_SUBMISSION_DRAFT.md
├── .gitignore
└── README.md
```
**Changes from the suggested structure:** there's no `pages/` folder or React Router because the app is a
single scrolling page; anchor links are enough. `config.py` was added to keep env handling in one place, and
`data/` holds static content so components stay focused on rendering.
